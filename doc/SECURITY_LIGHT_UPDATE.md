# 보안등 원본 파일 교체와 자동 반영

관리자가 할 일은 **마포구 공식 원본 CSV를 GitHub의 정해진 파일로 교체**하는 것입니다. 별도 웹 관리자 업로드 화면은 사용하지 않습니다.

## 파일 교체

1. 공공데이터포털 [전국보안등정보표준데이터](https://www.data.go.kr/data/15017320/standard.do)에서 마포구의 새 원본 CSV를 내려받습니다.
2. 파일 이름을 `security-lights-input.csv`로 바꿉니다. 열 이름·내용은 원본 그대로 유지합니다.
3. GitHub 저장소의 `backend/data/`에서 **Add file → Upload files**로 업로드하고 main에 커밋합니다. 팀에서 PR로 관리한다면 PR을 main에 병합하면 됩니다.
4. 파일 변경을 감지한 Actions **Collect safety facilities**가 자동으로 실행됩니다. 별도 실행 버튼을 누르지 않아도 됩니다.

입력 파일: `backend/data/security-lights-input.csv`
필수 열: `보안등위치명`, `소재지도로명주소`, `소재지지번주소`, `데이터기준일자`.
지원 인코딩: UTF-8(BOM 포함 가능), CP949. 마포구 외 원본과 빈 파일은 거부합니다.
최신 원본 다운로드와 이 파일 교체만 수동이며, 공공데이터 사이트의 자동 다운로드는 수행하지 않습니다.

## 자동 처리

원본 검증 → 기존 주소 좌표 재사용 → 새 주소·이전 미매칭 주소 조회 → 홍대 반경 필터링 → Zone 배정 → 보안등 DB 갱신.

- 주소가 동일하면 기존 좌표를 재사용합니다. 성공한 주소 좌표는 DB의 `security_light_address_cache`에 보존하며 삭제된 시설은 현재 원본 기준 스냅샷에서 빠집니다.
- 최초 실행에는 2026-10-15 검증된 주소 좌표도 재사용합니다. 변경된 주소는 새 주소로 조회하며, 이전 미매칭 주소는 재시도합니다.
- 복수 후보·주소 불일치·검색 실패는 확인 목록에 남깁니다. API 인증·연결 실패, 잘못된 원본, 대상 반경 결과 없음에서는 기존 시설 스냅샷을 교체하지 않습니다.
- 부분적으로 좌표가 확인된 정상 결과는 확인된 행만 저장합니다. 마포구 자료만 포함하고 미매칭이 있을 수 있어 `partial=true`, 주소 대표 좌표이므로 `estimated_coordinates=true` 표시를 유지합니다.
- 기존 스냅샷 교체는 수집원별 트랜잭션으로 처리합니다. CCTV·편의점·경찰시설·가로등 및 리뷰·안전점수는 이 파일 갱신 작업에서 변경하지 않습니다.

## 결과 확인

Actions 실행 요약에서 원본·변환 성공·반경 내·DB 저장 건수와 확인 필요 건수를 볼 수 있습니다.
같은 실행의 **security-light-update-results** 결과 파일은 30일간 내려받을 수 있습니다.

- `all_rows.csv`: 전체 원본과 변환 상태
- `geocoded.csv`: 주소가 일치한 행
- `hongdae_1km.csv`: 현재 설정한 반경 안의 행
- `needs_review.csv`: 별도 확인이 필요한 행
- `summary.json`: 실행 통계와 DB 저장 여부

실패한 경우 기존 원본·실행 요약을 확인하고 파일을 수정하면 재실행됩니다. 파일 변경 없이 재시도하려면 Actions의 Run workflow에서 source를 `security_light`로 선택합니다.
같은 파일을 그대로 다시 올려 Git 변경이 없으면 push 실행이 발생하지 않으므로 이 경우도 수동 재실행을 사용합니다.

## 실행 환경

기존 GitHub Secrets `KAKAO_REST_API_KEY`, `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`을 사용합니다. DB_PORT가 없으면 이 프로젝트의 TiDB 포트 4000입니다. 비밀 값은 원본 파일이나 프런트엔드에 넣지 않습니다.

로컬 실행: `cd backend` 후 `python update_security_lights.py`. 입력 경로와 출력 디렉터리는 `--input`, `--output-dir`로 지정할 수 있습니다.
기존 `collect_facilities.py`는 보안등의 과거 기본 파일을 재저장하지 않습니다. 보안등 기본 갱신에는 반드시 새 변환 명령을 사용합니다. 외부 조명 CSV URL/경로를 명시한 기존 수집 방식은 유지합니다.
기존 전체 정기 수집의 활성화 조건은 변경하지 않습니다. 이번 기능은 파일 교체 시 실행되는 자동 처리입니다.
