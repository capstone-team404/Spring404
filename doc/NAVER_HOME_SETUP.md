# 시작 화면·메뉴·홈 패널·네이버 계정 연결

## 반영된 화면
- 첫 진입 시 약 1.1초 동안 중앙에 여기지! 워드마크 표시. 로그인 상태면 지도, 비로그인 상태면 로그인으로 이동합니다. 기존의 지도 진입 방식은 유지합니다.
- 사이드 메뉴: 안전 지도, 내가 쓴 리뷰, 좋아요 한 리뷰, 신고 내역, 네이버 계정 연결, 마이페이지, 이용 안내. 관리자에게는 기존 관리자 메뉴도 표시합니다.
- 홈 바텀시트: 드래그 또는 손잡이 버튼으로 펼침/접기. 목적지 검색, 내 리뷰, 실제 Zone 정보량, 가까운 구역 5개, 지도 색상 안내를 제공합니다. 구역을 선택하면 기존 리뷰 화면이 열립니다.
- 가까운 구역은 현재 위치를 확보하면 현재 위치, 그 외에는 홍대입구역 기준입니다. 안전점수 순위나 실시간 시설 영업 정보가 아닙니다.
- 이번 변경은 기존 AI 점수·시설 점수·경로 정렬 계산식을 바꾸지 않습니다.

## 배포 전에 먼저 설정할 항목
코드를 올리기 전에 Render **백엔드**의 Environment를 준비하세요. AI 서버의 기존 환경변수는 유지합니다.

| 환경변수 | 값 |
|---|---|
| AUTH_VERIFICATION_MODE | `naver` (실제 계정 연결), `demo` (명시적인 개발·시연 환경만) |
| NAVER_CLIENT_ID | 네이버 개발자센터에서 발급된 값 |
| NAVER_CLIENT_SECRET | 네이버 개발자센터에서 발급된 비밀값 |
| NAVER_REDIRECT_URI | `https://hereji-backend.onrender.com/auth/naver/callback` |
| FRONTEND_URL | `https://spring404-bf9t.vercel.app` |

`AUTH_VERIFICATION_MODE` 미설정 시 기본값은 `naver`입니다. **기존 데모 확인 회원도 네이버 연결을 다시 해야 합니다.** 네이버 검수 전에는 앱 등록자·등록된 관리자·테스터만 연결을 테스트할 수 있으므로, 일반 이용자 공개 전에 검수가 필요합니다. 대기 중 기존 시연을 유지하려면 배포 전에 `AUTH_VERIFICATION_MODE=demo`를 명시하세요. 데모 코드 기능은 이 모드에서만 열리고 UI에서도 테스트임을 표시합니다. 실제 성별 확인이라고 설명하면 안 됩니다.

키는 Render에 직접 넣으며 GitHub·프런트엔드·채팅에 붙여넣지 않습니다. 현재 `AI_SERVICE_TOKEN`, `OPENAI_API_KEY`, 지도 키, DB 설정은 바꾸지 않습니다.

## 네이버 개발자센터
1. 서비스 URL: `https://spring404-bf9t.vercel.app`.
2. PC 웹·Mobile 웹의 Callback URL을 백엔드의 `NAVER_REDIRECT_URI`와 정확히 일치시킵니다.
3. 성별만 요청합니다. 이름·전화번호·이메일은 이 연결 기능에 필요하지 않습니다. 이용자 식별자는 기본 제공됩니다.
4. 멤버관리에 실제 테스트할 네이버 ID를 등록합니다. 앱 등록자 계정은 별도 추가 없이 사용할 수 있습니다.
5. 프런트엔드와 백엔드를 함께 배포합니다. 프런트엔드 `VITE_API_URL`은 기존 백엔드 주소를 유지합니다. `VITE_` 변수에 네이버 비밀키를 추가하지 않습니다.

## 저장 및 연결 처리
- 기존 이메일 로그인 후 별도로 네이버 계정을 연결합니다. 네이버로 신규 회원가입하는 기능은 아닙니다.
- 동의 체크 후 연결을 시작하며 네이버 프로필의 `gender=F`인 경우만 완료합니다. 미제공·U·다른 값은 완료 처리하지 않습니다.
- 네이버 계정에 등록된 성별 확인입니다. 본인확인 기관의 인증, 실제 방문, 리뷰의 진실성을 보장하지 않습니다.
- 서버가 일회용 state의 해시를 회원별로 저장하고, 유효기간 10분·로그인 회원 일치·단일 사용을 확인합니다. 콜백만 열어서는 회원 상태가 바뀌지 않습니다.
- 네이버의 이용자 식별자 해시와 연결 회원 ID, 확인 시각을 저장합니다. 프로필 전체·이름·전화번호·네이버 접근/갱신 토큰은 저장하지 않습니다.
- 네이버 계정 한 개를 여러 여기지 회원에게 연결하거나, 연결된 계정을 임의로 바꾸는 것을 차단합니다.
- 회원 탈퇴 시 로컬 네이버 연결 정보와 대기 중 연결 요청을 삭제합니다. 네이버 측 연결 해제는 네이버 계정의 연결 서비스 관리에서 별도로 진행할 수 있습니다. 로컬 탈퇴가 네이버 동의를 자동 철회하는 기능은 아닙니다.
- DB 시작 시 `verification_provider` 열과 `naver_account_link`, `naver_link_state` 테이블이 추가됩니다. 기존 리뷰 데이터는 삭제하지 않습니다.

## 실제 배포 후 확인
1. 로그아웃 상태에서 새로고침: 로고 → 로그인. 로그인된 상태에서는 로고 → 지도 또는 성별 확인 화면.
2. 미확인 회원: 안내 확인 → 동의 체크 → 네이버 계정 연결. 완료 후 지도 진입.
3. 메뉴 → 네이버 계정 연결: `네이버 계정 성별 확인 완료` 표시.
4. 미동의·성별 미제공·연결 취소: 이유를 표시하고 확인 완료로 넘어가지 않는지 확인.
5. 다른 여기지 계정에서 같은 네이버 계정 연결: 중복 연결 거절 확인.
6. 연결 중 여기지 로그아웃/다른 회원으로 로그인, 만료된 요청·재사용 요청: 거절 확인.
7. 홈 손잡이를 탭하거나 드래그: 확대·축소, 내부 목록 스크롤. 가까운 구역 → 기존 구역/리뷰 화면. 메뉴의 내 리뷰·좋아요·신고·이용 안내 이동 및 지도 복귀.
8. 휴대폰 브라우저에서 같은 과정 확인. 네이버 앱 전환 후에도 원래 브라우저 로그인 상태로 돌아오는지 확인.

## 검수 자료
네이버 연결 버튼 → 정보 이용 안내/동의 → 네이버 로그인·정보 제공 동의 → 완료 표시까지 실제 화면을 순서대로 캡처합니다. 성별 확인을 어떤 기능에 사용하는지도 실제 화면과 함께 제출합니다. 이 구현은 기존 회원의 계정 연결이므로 해당 형태를 정확히 설명하세요. 승인 여부는 네이버 검수에서 판단하며, 승인 전부터 일반 네이버 계정 모두가 사용 가능한 것으로 안내하면 안 됩니다. 네이버 신규 가입을 도입하는 경우 서비스 자체 비밀번호를 추가 요구하지 않는 별도 흐름이 필요합니다.

## 개발 검증
- Python: `python -m pytest tests -q --disable-warnings`.
- 프런트엔드: `npm run build`.
- 브라우저: 빌드 후 `npm run preview -- --host 127.0.0.1 --port 5175`. Playwright 설치 환경에서 `node tests/ui_navigation.cjs`. 필요하면 `UI_BROWSER_PATH`에 Chromium 계열 실행 파일, `UI_SCREENSHOT_DIR`에 결과 경로를 지정합니다.
- 브라우저 테스트는 지도 SDK와 서버 API를 모의 처리합니다. 화면 이동·드래그·동의·콜백 처리 검증이며 실제 지도 타일, 실제 네이버 권한 및 검수 승인을 확인한 것은 아닙니다. 실제 키로 연결 테스트를 마쳐야 합니다.
