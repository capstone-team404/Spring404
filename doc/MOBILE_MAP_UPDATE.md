# 로고·모바일 지도 터치·UI·길찾기 메뉴 개선

## 변경 내용
1. 첫 진입의 텍스트 워드마크를 제공받은 로고로 교체했습니다. 원본 PNG를 수정 없이 포함합니다. 이미지 로딩 후 약 1.1초 표시하고 기존 로그인/지도 진입 흐름을 유지합니다. 이미지가 로드되지 않아도 최대 5초 후 진행합니다.
2. TMAP 지도 컨테이너의 네이티브 터치 이벤트를 관찰하여 짧은 한 손가락 탭으로 구역을 선택합니다. 지도 범위의 Web Mercator 좌표로 터치 위치를 변환하며 이동 후에도 현재 지도 범위를 사용합니다. 드래그·핀치 확대·길게 누르기·취소된 터치는 선택에서 제외하고, 이어지는 SDK click 중복 처리를 막습니다. 지도 이동/확대를 막는 preventDefault는 사용하지 않습니다.
3. 검색바, 홈 패널, 사이드 메뉴, 로그인, 구역/경로 상세의 간격·글꼴 굵기·테두리·아이콘을 정돈했습니다. 구역의 초록/노랑/빨강/회색 의미와 실제 점수는 유지합니다. 리뷰가 없는 경우 별점 0 대신 '리뷰 없음'을 표시합니다.
4. 상단과 사이드 메뉴, 홈 패널의 길찾기가 같은 출발지·도착지 선택 화면으로 연결됩니다. 장소 검색, 현재 위치, 출발·도착 교환을 제공하고 기존 TMAP 후보 생성 및 백엔드 안전점수 정렬을 그대로 사용합니다. 부가 메뉴는 '더 보기'에 유지합니다.

네이버 정책 검토·성별 제한·회원가입/로그인 로직은 이번 변경에서 수정하지 않았습니다. 시설점수·AI 분석·경로 순위 계산식도 바꾸지 않았습니다.

## 반영 방법
- 팀 저장소 main `ebd783c` 기준으로 작업했습니다. 그 이후 같은 파일에 팀원 수정이 있다면 비교 후 반영하세요.
- ZIP 자체를 업로드하지 말고 압축을 풀어 내부 파일을 저장소의 같은 경로에 반영합니다. 이미지와 신규 JS/CSS도 모두 필요합니다.
- 권장 작업 브랜치: `feature/mobile-map-polish`. 기존 `backend`, `ai` 파일이나 실제 `.env`를 덮어쓰지 않습니다.
- 새 환경변수나 추가 서버는 필요하지 않습니다. Vercel 프런트엔드를 배포하면 됩니다. 기존 `VITE_API_URL`, `VITE_TMAP_APP_KEY`를 유지합니다.
- 로컬 빌드에서는 지도 키가 없어 경고가 나지만 배포 환경의 기존 지도 키를 계속 사용합니다.

## 실제 휴대폰에서 확인할 순서
1. 새로고침: 중앙 로고 → 기존 로그인 또는 지도. 로고가 잘리지 않는지 확인합니다.
2. 지도에 보이는 색칠된 구역을 한 번 탭: 해당 구역 이름·점수·리뷰가 열리는지 확인합니다.
3. 상세를 닫고 다른 구역 탭: 다른 구역이 열리는지 확인합니다. 초록/노랑/빨강/회색 중 가능한 구역들을 각각 확인합니다.
4. 한 손가락으로 지도 이동: 이동만 되고 구역이 자동 선택되지 않아야 합니다.
5. 두 손가락으로 확대/축소하고 손가락 떼기: 구역이 자동 선택되지 않아야 합니다. 확대/이동한 뒤 다시 탭해 현재 구역이 선택되는지 확인합니다.
6. 바텀시트 손잡이 드래그·탭, 목록 내부 스크롤이 각각 동작하는지 확인합니다.
7. 사이드 메뉴 → 길찾기 → 출발지 검색/선택 → 도착지 검색/선택 → 경로 비교. 지도와 후보·거리·시간·안전점수가 나타나는지 확인합니다.
8. 출발·도착 교환, 현재 위치 허용/거절, 검색 결과 없음, 길찾기 닫기와 다시 열기를 확인합니다. 현재 위치를 거절해도 장소 검색으로 출발지를 정할 수 있습니다.
9. '더 보기'의 좋아요·신고·네이버 연결·이용 안내와 마이페이지 이동이 유지되는지 확인합니다.
10. PC 마우스 구역 클릭·지도 이동도 확인합니다. 가능하면 Android Chrome 및 iPhone Safari에서 각각 확인합니다.

네이버 검수 전 계정 이용 범위는 이번 변경으로 달라지지 않습니다. 학생들의 공개 접속 가능 여부는 별도의 계정/운영 정책입니다.

## 개발 검증
- 기존 Python 테스트: 75개 통과.
- `node tests/map_interactions.mjs`: 단일 탭, 중복 click 방지, 드래그·핀치·롱프레스·취소 제외, 리스너 정리, 투영 좌표·구역 경계 검증.
- `npm --prefix frontend run build`: 통과.
- `tests/ui_navigation.cjs`: 데스크톱·모바일 터치 에뮬레이션에서 로고, 로그인, 패널 드래그, 메뉴, 네이티브 구역 탭(조회 1회), 길찾기 검색/후보 정렬, 기존 네이버 연결 화면·콜백을 확인합니다. 지도 SDK와 API는 모의 데이터로 대체하며 실제 네이버/OpenAI 호출은 없습니다.
- 실제 TMAP 타일과 iPhone/Android 기기의 이벤트 조합은 배포 후 위 순서로 확인해야 합니다. 모의 테스트 결과를 실제 휴대폰 검증 완료로 해석하면 안 됩니다.

참고: [TMAP V2 지도/범위 공식 문서](https://tmapapi.tmapmobility.com/main.html#webv2/docs/WebDocs.Tmap), [네이티브 터치 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/Touch_events/Using_Touch_Events).
