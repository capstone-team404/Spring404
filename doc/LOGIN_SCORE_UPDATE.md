# 로그인·점수 개편 (2026-11-05)

> 점수 부분은 당시 experience-v2 기록입니다. 최신 시설 연동 기준과 배포 방법은 `FACILITY_SCORE_INTEGRATION.md`를 확인하세요. 로그인 기준은 변경하지 않습니다.

기준: 팀 저장소 main 880fb4a. 여성 1인 여행자의 경험을 모으되 지도 이용을 계정 연결 단계로 막지 않는 구성입니다.

## 이용 흐름

- 첫 화면: 이메일 로그인/회원가입, 네이버로 시작하기, 로그인 없이 지도 둘러보기.
- 이메일 가입 직후 지도 이용 가능. 기존 계정·리뷰 유지.
- 네이버 첫 로그인: 별도 서비스 비밀번호 없이 가입. 안내 동의 후 진행하며, 임의 닉네임은 마이페이지에서 수정 가능.
- 네이버 이용자 식별자의 해시와 계정 연결 상태를 저장. 이름·실제 이메일·전화번호·네이버 접근/갱신 토큰은 저장하지 않음. 내부 식별용 이메일 형식은 사용자에게 노출하지 않음.
- 지도·구역 정보·리뷰 조회·경로 비교는 연결 없이 이용 가능. 활동 내역·좋아요·신고는 로그인 필요.
- 리뷰 작성/수정은 여성으로 등록된 네이버 계정 연결 필요. 네이버로 로그인해도 등록 성별이 없거나 조건과 다르면 지도 이용은 가능하지만 리뷰 작성 권한은 부여하지 않음.
- 이메일 사용자는 마이페이지 → 네이버 계정 연결. 연결한 네이버 계정으로도 같은 여기지 계정에 로그인 가능. 다른 계정에 이미 연결된 네이버 계정은 자동 병합하지 않음.
- 로그인 화면에 긴 본인확인 설명을 노출하지 않음. 계정 연결의 펼침 안내에 정보 사용 범위와 한계를 명시. 본인확인이나 방문 인증으로 표현하지 않음.

네이버 검수 승인은 별도입니다. 승인 전에는 등록한 관리자·테스터 계정으로 확인해야 합니다. 이 구현만으로 검수가 통과되거나 등록 성별의 정확성이 보장되는 것은 아닙니다.

## 점수 기준 experience-v2

1. 리뷰 한 건: 사용자 별점 80% + 텍스트 분석 점수 20%. AI 점수와 별점이 다르다는 이유로 신뢰도를 감점하지 않음.
2. 같은 작성자의 구역 내 리뷰를 가중 평균한 뒤 한 사람의 반영량을 최대 1로 제한. 숨김·삭제·반영 제외 리뷰는 사용하지 않음.
3. 구역 리뷰 점수: `(작성자별 점수×반영량 합 + 3×2) / (반영량 합 + 2)`. 표본이 적을 때 3점의 중립 기준으로 급변을 완화. 3점은 관측 자료가 아닌 계산용 사전값.
4. 시설이 관측된 경우 기존 시설 점수를 `(시설 점수×관측 시설 수 + 3×3)/(관측 시설 수+3)`으로 완충. 시설이 적다는 사실을 곧바로 위험으로 해석하지 않음. 기존 원점수 변환 `PUBLIC_SCORE_BOOST/OFFSET`은 유지.
5. 리뷰·시설이 모두 있으면 리뷰 70% + 시설 30%. 한쪽이 없으면 있는 자료만 사용. 둘 다 없으면 정보 부족(회색).
6. 작성자 3명 미만 또는 시설만으로 계산한 점수는 구역 상세에 '초기 참고 점수' 표시. 리뷰가 쌓이면 사전값의 영향이 줄어듦.
7. 기존 OpenAI/규칙 분석 리뷰의 반영량도 저장된 텍스트로 읽을 때 다시 산정. 기존 모델 점수·요약을 유료 재분석하거나 DB에서 일괄 덮어쓰지 않음.
8. 정보 부족 구역의 호환용 숫자 0은 지도에서 점수로 표시하지 않고 경로 최저·평균 점수 계산에서도 제외. 경로 데이터 적용 비율에 반영.

예시(모든 반영량 1, 시설 자료 없음): 별점 5·분석 1인 리뷰는 리뷰 자체 4.2점, 한 명일 때 구역 3.4점. 같은 사람의 같은 점수 리뷰 100개도 구역 3.4점. 서로 다른 10명이 별점·분석 모두 1점이면 구역 1.33점으로 낮은 평가가 유지됩니다.

위 수치들은 초기 설계값이며 검증된 범죄 예측 확률이 아닙니다. 데이터 부족을 감추려고 전체 점수에 일괄 가산하거나 실제 리뷰를 생성하지 않았습니다. 수집 자동화의 시설 현황과 기존 `public_safety_zone` 점수 자료는 여전히 별도이므로, 시설 수집 성공만으로 점수용 데이터가 자동으로 완성되었다고 볼 수 없습니다. 이후 출처·날짜·좌표 정확도와 커버리지를 확인한 뒤 연결해야 합니다.

## 배포

1. 변경 파일을 같은 상대 경로로 반영. 신규 `backend/score_policy.py`도 반드시 포함.
2. Render AI 재배포 → Render backend 재배포 → Vercel frontend 재배포.
3. 기존 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `NAVER_REDIRECT_URI`, `FRONTEND_URL`, `AUTH_VERIFICATION_MODE=naver`, 양쪽 `AI_SERVICE_TOKEN` 유지. 새 키나 유료 서비스를 요구하지 않음.
4. 콜백 주소는 기존 backend `/auth/naver/callback` 그대로. 별도의 네이버 콜백 등록 불필요.
5. backend 시작 시 `naver_login_state` 테이블 추가 생성. 기존 회원·리뷰 삭제나 수동 SQL 실행 불필요. 기존 `REVIEW_WEIGHT/PUBLIC_WEIGHT` 환경변수 대신 버전이 명시된 `score_policy.py` 기준을 사용.
6. 네이버 검수 자료는 실제 '네이버로 시작하기 → 동의 → 서비스 이용'과 이메일 계정 연결 화면에 맞춰 다시 준비.

## 확인 시나리오

- 로그아웃 → 지도 둘러보기 → 모바일 구역 터치 → 리뷰 조회 → 길찾기.
- 이메일 가입/로그인 → 지도 → 리뷰 저장 시 계정 연결 화면 → 네이버 연결 → 리뷰 작성.
- 테스트 네이버 계정 첫 로그인 → 가입 → 재로그인 시 같은 계정/리뷰 유지.
- 네이버 로그인 취소/만료 → 오류 안내 후 이메일 또는 지도 둘러보기로 이용 가능.
- 기존 이메일 계정에 연결된 네이버로 로그인 → 동일한 계정인지 확인.
- 정보 없는 구역은 회색, 적은 자료는 초기 참고 표시. 좋은 리뷰 한 건으로 즉시 5점이 되지 않으며 여러 작성자의 낮은 평가는 여전히 빨강.
- 새 리뷰 응답의 `analysis_source=openai` 확인. 이 변경 때문에 별도 OpenAI 재분석 비용은 발생하지 않음.

로컬 검증은 실제 API 키·운영 DB를 사용하지 않는 테스트입니다. 네이버 심사 승인, 운영 TiDB의 동시 트랜잭션, 실기기 지도 SDK와 배포 환경변수는 배포 후 별도로 확인해야 합니다.
